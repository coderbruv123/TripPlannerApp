Design review · mock v1

What I'd change, and why

These are observations from actually running the web app (backend + SQL Server + Vite, demo account, real destination lookup and a real /api/trips/search response), not guesses from reading code. Everything below is what the mock proposes — nothing is applied to the app yet.

Bugs

Broken while running it

Route panel is nested inside the map card (desktop and mobile)
The “How do you want to travel?” panel is a child of the destination card. Measured at 1440px it renders 102px wide and 418px tall inside a 158px card; at 390px it sits at x=489, fully off-screen. The map pane also measures 0px wide on phones.
TripResults.tsx — unbalanced divs before the transport block; sidebar is fixed at 380px with no breakpoint
“From $” with no number
The routing API returns estimatedPrice: null. The check is !== undefined, so null passes and renders “From $” with an empty value. Same for the stop summary.
TripResults.tsx — price conditions
Geolocation is a hard requirement — denial is a dead end
Plan My Trip calls getCurrentPosition with no manual origin fallback. Deny it, or fail inside a browser without a location provider, and the only feedback is an alert().
Hero.tsx — Plan My Trip handler
Destination search returns districts, not cities
Typing “Paris” returns ten arrondissements; Santorini returns an empty list even though it's the hardcoded fallback destination on the trip page.
DestinationService.cs — namePrefix only, no feature-class filter or ranking
Signed-in users see a “Sign in” button
The trip workspace header hardcodes the auth CTA while the user is authenticated; it also duplicates the global navbar with a different brand mark.
TripResults.tsx — header
CORS blocks 127.0.0.1
Only localhost:5173 and :3000 are allowed, so opening the dev server at 127.0.0.1 makes every API call fail with an opaque “Unable to sign in”.
Program.cs — ReactPolicy; Vite binds 127.0.0.1 by default
Planner fields collapse to 118px and the card sits below the fold
At 1280px the 5-column grid has only 4 children, so “Dates” renders 118×117px with a wrapping label. On a 768px-tall laptop the planner card starts below the fold.
Hero.tsx — grid-cols-[2fr_1.3fr_1.2fr_1fr_auto] with 4 items
Dead controls
Explore / Travelers / Places only toggle icon colour; the add-destination input accepts text and never submits; the hotel hearts and badges are decorative; “Saved” is local state only.
TripResults.tsx, HotelStays.tsx

Features

Worth adding next

1
Persist trips end to end
Save/load from the API, resume drafts, duplicate a trip. The Save button should write to the backend, not local state.
High impactBackend + frontend
2
Day-by-day itinerary with time-aware legs
Stops per day, auto-inserted travel legs between them, drag to reorder, opening-hours warnings. This is the feature the home page already promises.
High impactFrontend
3
Real stays from the hotel service
HotelService (OSM/Overpass) already exists and is unused by the UI. Feed the home page and the trip panel from it with skeletons, empty and error states.
High impactWire-up
4
Honest availability and pricing
Badges for Fastest / Cheapest / Recommended, “fare unavailable” instead of “$0” or “From $”, disabled modes with a reason, estimated-data labels.
High impactFrontend
5
Budget with categories and per-person split
Transport, stays, food, activities; projected vs actual; over-budget warnings; currency and per-person/or-group toggle.
MediumFrontend
6
Manual origin + saved places
Type an origin, choose “use my location”, or pick a saved address. Add bookmarkable POIs to a trip from the map.
MediumFrontend
7
Share, export, collaborate
Read-only share link, .ics and PDF export, invite travellers with per-person budget. Route data is already in the app state.
MediumFull stack
8
Weather and daylight on the itinerary
Forecast for the trip dates, sunset times for viewpoints, “indoor option” suggestions when rain is likely.
LaterAPI
9
Unified shell and one palette
Today: teal navbar, indigo CTA, sky/emerald gradient banner, dark-green admin, and a separate dark mode that only exists on one page. Consolidate into tokens and one app shell with a global theme.
High impactRefactor
Components

New pieces this design needs

A
SearchCombobox
Debounced, keyboard-navigable, grouped results, loading and empty states, recent searches. Replaces both the hero input and the dead add-destination field.
B
DateRangeField + TravelersField + BudgetField
Shared field shell (label / value / sub / popover), min-date and ordering constraints, nights count, per-person math, currency input with formatting.
C
ItineraryTimeline + StopCard + TransportLeg
Day tabs, reorderable stops, computed legs, empty-day suggestions. The single biggest visual and functional win on the trip page.
D
TransportOptionList
Radio-style rows with badges, disabled reasons, estimated flags, fare fallbacks. Fixes the nested/overflowing panel by moving it into its own column.
E
BudgetMeter
Category bars, remaining amount, warning colour above 90%. Reads from the same trip state as the itinerary.
F
Skeleton / EmptyState / Toast
Replace alert() and silent failures. Skeletons for search and stays, empty states with next actions, toasts for save/export errors.
