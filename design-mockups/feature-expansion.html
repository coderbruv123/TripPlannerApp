Design notes
Design notes · mock v3

Eight features the app is missing
after it gets the basics right.

Mock v1 covered the planning flow: search, itinerary, transport, stays. Mock v2 covered auth, account and admin. This one covers what happens around the trip — choosing a starting shape, fixing a day, running the day from your phone, sharing it, paying for it, keeping the paperwork, and remembering it afterwards.

Features

What this mock proposes

1
Start from a template
A gallery of real itineraries — stops, durations, coordinates, opening hours — that you duplicate into a trip you own. Fixes the blank-page problem without pretending to be an LLM. Never mutates the source.
High impactFull stackSeed content
2
Day optimizer with a visible diff
Reorder one day against real constraints: opening hours, holiday closures, sunset, walking budget, timed tickets. Show the before/after, the minutes saved, and why each stop moved — then let the user apply or undo.
High impactFrontend + matrix API
3
Today / live trip mode
The screen people actually open on holiday: next stop, leave-by time, directions, check-in, running late, ticket windows, weather swaps. Large touch targets, works one-handed, survives refresh.
High impactFrontendPush
4
Group planning
Invite travellers with owner/editor/viewer roles, collect suggestions in an inbox, vote on them, and see who is booking what. Turns the app from solo planning into the group chat that replaces five other chats.
High impactFull stackMembership
5
Expense splitting and settle-up
Log who paid, split per person, keep balances in integer cents, and compute the fewest transfers. This is the natural extension of the budget panel — and it does not need a payments integration to be useful.
High impactFrontend + schema
6
Travel vault
Tickets, bookings, insurance and passport scans filed per trip, shared by role, expiring-document reminders, and an offline pack that includes the QR codes. The 3am-at-the-airport feature.
MediumStorage + signed URLs
7
Journal and trip recap
Notes and photos attached to the day they happened, auto-assembled into a recap with distance walked, stops kept and money spent. Private by default, shareable as a read-only story. Gives the trip a second life after it ends.
MediumFrontend + storage
8
Offline pack (PWA)
Service worker caches the day plan, tickets and map tiles for the trip. Shows staleness honestly ("saved 11:40") instead of pretending to be live. Cross-cutting: every other feature degrades gracefully without it.
MediumPWACross-cutting
Sequence

Build order that doesn't block

1
Money over existing trip state
No schema change to start: expenses can live against the trip ID you already persist. Highest value per hour of work, and it exercises the shared-trip model.
2
Optimizer, client-side first
Opening hours and sunset are local data; the walking matrix is the only server call. Ship the diff UI with a fixed matrix, then swap in OpenRouteService.
3
Persist trips, then group
Group planning is not real until trips live in the database with owner IDs. This is the prerequisite v1 already flagged — do it before invites, votes or activity.
4
Templates, vault, journal, offline
Each is independently shippable. Templates need editorial seed content; vault needs storage; journal needs uploads; offline needs a service worker. None should block the others.
Components

New pieces

A
TemplateGallery + TemplateCard
Filter chips, route thumbnail, copy-on-use with a confirmation that names the source.
B
ConstraintChips + StopDiffList
Toggleable goals, moved-from badges, "why" reasons, apply/discard with undo snapshot.
C
NextUpCard + LeaveByBar + CheckInButton
Countdown, computed leave time, one-tap check-in, late broadcast.
D
MemberList + RoleSelect + SuggestionCard + PollCard
Invites, roles, votes, activity feed. Optimistic updates with rollback on failure.
E
ExpenseTable + SplitPicker + BalanceList + SettleUpSheet
Integer cents only, per-expense splits, minimal-transfer algorithm, CSV export.
F
DocRow + ExpiryBadge + OfflinePackCard
Per-document sharing, passport/insurance reminders, cached-state timestamps.

Deliberately not here

What I left out

×
AI itinerary generation
Templates solve the blank page with data you can verify. An LLM layer is a different product and a different trust problem.
×
In-app payments
Settle-up records that money moved; it never moves money. No PCI scope, no payout liability.
×
Real-time co-editing
Suggestions, votes and an activity feed cover group coordination. CRDT cursors on an itinerary are engineering cost without a matching user need.

This file is standalone — no build step, no backend, no external fonts or scripts. Use the bar at the top to switch screens, the moon icon for dark mode, and #today in the URL to deep-link a screen. Colours and spacing come from the same token set as mock v1, so these pieces can be dropped into TripApp-Web as-is.
